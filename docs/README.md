# Документация Loadvision

Точка входа для человека или агента, который открыл репозиторий и не знает, с чего начать.

Задача: по фото грузового отсека и номеру перевозки вернуть загрузку 0-100%, сохранить её, отдать по XML API и уметь дообучаться на подтверждённых метках. Метрика - MAE в процентных пунктах. Дедлайн 22.09.2026 23:59.

## Правила, добытые замерами

- **Шум разбиения около 0.3.** Улучшение меньше 0.35 на одном сиде улучшением не считается.
- **Публичный лидерборд имеет погрешность ±1.26** (153 фото). Наш OOF вдвое точнее. Решения принимаем по OOF на трёх сидах, платформу используем как контроль «не сломали ли грубо».
- **Улучшение среднего при ухудшении сценария** - повод разобраться, а не праздновать. Таблица сценариев в каждом прогоне, `runs/<прогон>/cases.json`.
- **Метка это доля занятой площади пола**, не глубина. Опровергнуто наблюдением 17.09.
- **Одна величина - одна реализация.** Декодирование, яркость, округление, обрезка в 0-100: все четыре уже расходились между обучением и сервисом. Где расхождение возможно, нужен тест, который его ловит, а не ручная сверка на десятке фото.

## Порядок ML-цепочки

Один запуск - шесть этапов, каждый со своими постусловиями:

```
build_manifest       фото и метки -> manifest.csv, проверки целостности
extract_embeddings   замороженные энкодеры -> векторы в кэш по sha256
train_folds          голова на 4 фолдах -> предсказание 5-го -> oof.csv
evaluate             oof.csv -> metrics.json, cases.json, worst_oof.csv
predict_test         голова на всех метках -> submission.csv
build_package        головы, кривые, веса, манифест -> package/
```

Запуск: `uv run python scripts/run_pipeline.py configs/experiments/<имя>.json --device mps`.
Результат - папка `runs/run_<время>_<хвост>/` с `summary.json`, `run.jsonl` и артефактами.

Подробности каждого шага - в `ml/pipeline.md`.

## Что дальше, по порядку

**Must, куски владельца A:**

1. **Тексты лицензий в пакете** - Apache-2.0 требует прикладывать лицензию и NOTICE при распространении весов. Поле `licenses` в манифесте есть, `build_package` его не заполняет. Полчаса работы, закрывает хвост К7.
2. **`extend_folds`** - новые метки получают фолд по правилу 3 контракта, старые строки не двигаются. Без этого gate сравнивает несравнимое. Тест: добавили 30 строк, фолды исходных 716 не изменились.
3. **Импорт подтверждённых меток** - CSV организаторов плюс фото из хранилища в дополненный датасет.
4. **`TrainingRunner`** - порт в `application/ports.py` есть, реализации нет. Собирает этапы и отдаёт `TrainingOutcome`.
5. **Gate** - MAE кандидата против активной на общих старых строках, минимум новых меток и допуск.
6. **README** - метрики CV, скорость с железом, ограничения, пункты условия.

**Must, куски владельца B:** API, воркер, активация версии и откат, образы, развёртывание.

**Should, если останется время:** срезы по типам груза (организаторы перечислили типы явно), стресс-тест устойчивости, оценка веса как описанное расширение без числа в ответе.

## Открытые вопросы к владельцу B

- Порог неуверенности для флага `low_confidence` описать в манифесте нечем: у `ood` есть `threshold`, у неуверенности нет. Предложение - `review: {uncertainty: float}` рядом с `ood`.
- `too_dark` и `blurry` сервис **не выставляет**: замер показал, что в наших данных они ошибку не предсказывают. В XSD причины остаются.
- Этап `build_package` кладёт веса копией из кэша Hugging Face - это заготовка под его `model pull`.

## Команды

```
uv sync                                   поставить всё
scripts/check.sh                          ruff, pyright, import-linter, быстрые тесты
uv run pytest -m data                     проверки на реальном датасете, нужен data/
uv run python scripts/make_folds.py       собрать configs/splits/folds.json
uv run python scripts/make_folds.py --check   только проверить файл
uv run python scripts/probe_encoders.py   kNN-зонд по реестру энкодеров, без обучения
uv run python scripts/run_pipeline.py configs/experiments/ens4_apache_by_aspect.json --device mps   весь пайплайн
uv run python scripts/evaluate.py         перебор энкодеров и голов по OOF
uv run python scripts/evaluate_postprocess.py   перебор цепочек постобработки
uv run python scripts/analyze_errors.py   отчёт по ошибкам с графиками в runs/eda/
```

Скрипты в `scripts/` - исследовательские: они перебирают варианты и пишут историю в `runs/`.
Пайплайн - производственный: он считает одну конфигурацию из конфига и оставляет папку прогона.

## Правила ведения документации

- решение зафиксировано - строка в `plan/notes.md` с датой и причиной
- проверенный факт про библиотеку или лицензию - в `plan/facts.md`, со ссылкой
- замер - строка в `ml/experiments.md` и, если он повторяемый, запись в `runs/`
- вопрос без ответа - в `plan/open-questions.md` с владельцем
- спека контракта меняется вместе с кодом, в одном коммите
