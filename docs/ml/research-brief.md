# Бриф для внешнего исследования (Deep Research)

Самодостаточный текст: его можно скопировать целиком в Google Deep Research или другой инструмент, у которого нет доступа к репозиторию. Обновлять вместе с `experiments.md`, когда меняются цифры.

Версия от 17.09.2026.

## Задача

Хакатон Почты России, дедлайн 22.09.2026. Нужен MVP сервиса: на вход одна фотография грузового отсека машины, на выход число от 0 до 100 - **доля занятой площади пола кузова**. Результат сохраняется по номеру перевозки и отдаётся через XML API, плюс требуется воспроизводимое дообучение на подтверждённых людьми метках.

Метрика автоматической оценки: **MAE в процентных пунктах**, меньше лучше. Дополнительно считаем долю прогнозов с абсолютной ошибкой не больше 10 п.п.

Отдельно идёт экспертная оценка: качество API, скорость обработки с учётом оборудования, полезность дополнительных функций.

## Данные

- Всего 1023 фотографии: **716 train** с метками, **307 test** без меток (153 в публичном рейтинге, 154 в приватном).
- Формат JPEG, разные ракурсы, освещение, типы кузовов и грузов. Типы груза по условию: палеты, металлические тележки-контейнеры, штабелируемые пластиковые контейнеры, почтовые мешки, посылки навалом.
- Есть `train_groups.csv`: **группы визуально похожих кадров** - один и тот же кузов, снятый несколько раз. 660 групп на 716 фото, то есть в основном по одному-два кадра на группу.
- Распределение меток сильно неравномерное: **19-20% меток ровно 100**. Метка 0 тоже встречается. Середина диапазона разрежена.
- Разметка шумная: это экспертная глазомерная оценка, а не измерение.
- Внешние данные и псевдоразметку тестовых фото команда решила не использовать.

## Что уже построено и какие цифры получены

Архитектура: **замороженный предобученный ViT-энкодер → эмбеддинг → гребневая регрессия → усреднение ансамбля из 4 членов → условная калибровка → округление до 5**.

Текущий результат:

| Что | Значение |
|---|---|
| MAE на честной кросс-валидации (716 фото, 5 фолдов, группы не разъезжаются) | **6.47** |
| Доля ошибок не больше 10 п.п. | 85.1% |
| MAE на публичном рейтинге платформы (153 фото) | **7.10** |
| Baseline организаторов (Ridge по цветовым признакам) | 19.1 |
| Задержка на CPU, 4 потока, одно фото | 879 мс |

Валидация: `StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=0)`, стратификация по 11 бинам метки (десятки плюс отдельный бин для ровно 100), группировка по `group_id`. Фолды зафиксированы в файле и никогда не меняются для уже размеченных фото.

### Замеренные факты, которые не надо перепроверять

Всё ниже измерено на наших данных. Исследование должно **опираться** на это, а не повторять.

1. **Шум разбиения около 0.3 MAE.** Один и тот же ансамбль на трёх разных сидах разбиения даёт такой разброс. Улучшение меньше 0.35 на одном сиде мы не считаем улучшением.
2. **Публичный лидерборд имеет собственную стандартную ошибку ±1.26** (153 фото при стандартном отклонении модуля ошибки 7.77). Наш OOF вдвое точнее. По лидерборду ничего не подбираем.
3. **Пространственная сетка важнее выбора энкодера.** Усреднение патч-токенов внутри сетки 4×3 вместо общего вектора энкодера: у SigLIP 2 MAE 10.44 → 9.39, у остальных 0.2-0.3. Это прямое следствие того, что метка - доля площади пола, а общий вектор описывает сцену целиком. Признаков у сеточного варианта 9216 против 768.
4. **Сила регуляризации важнее выбора энкодера.** На одном энкодере alpha от 0.1 до 200 меняет MAE с 19.1 до 8.87. Оптимум alpha для 768 признаков около 50-300, для 9216 признаков около 1000-3000.
5. **Лучшие одиночные энкодеры почти не отличаются:** PE-Spatial ViT-B/16 сетка 4×3 с нейтральной заливкой полей 8.61, DINOv3 ViT-B/16 сетка 8.63, PE-Spatial общий вектор 8.97, SigLIP 2 сетка 9.39, DINOv2 ViT-B/14 общий вектор 10.45.
6. **Усреднение ансамбля даёт около 0.5**, конкатенация векторов в одну длинную строку - хуже усреднения.
7. **Головы, обученные на квадрат ошибки, тянут ответ к середине.** На метке 100 средний сырой прогноз 94.6, на метке 0-5 он 7.0. Калибровка по медиане в 16 бинах плюс округление до 5 снимает 1.90 пункта MAE (8.37 → 6.47).
8. **В датасете две популяции, различимые по пропорциям кадра.** У фото с отношением ширины к высоте 0.70-0.80 доля меток «ровно 100» равна 30.8%, у остальных 7.4%. Отдельная калибровочная кривая на каждую популяцию даёт значимый выигрыш 0.60 ± 0.18.
9. **Середина диапазона - главная оставшаяся потеря.** MAE по истинной метке: 0-20 → 4.44, 20-80 → **9.71**, 80-100 → 5.07.
10. **Яркость кадра не предсказывает ошибку** (связь идёт в обратную сторону), **резкость не коррелирует с ошибкой вовсе**. Оба сигнала мы отказались показывать пользователю.
11. **Почти-дублей в датасете нет:** максимум косинусной близости между разными группами 0.964 при пороге дубля 0.98.
12. **kNN-зонд по эмбеддингам врёт при выборе энкодера:** по нему лидировал SigLIP 2, с обученной головой он на пятом месте.
13. **Bicubic против bilinear при ресайзе: +0.08**, то есть шум.
14. Препроцессинг: вписывание в рамку 512×384 (3:4) с сохранением пропорций. Заливка полей нейтральным цветом энкодера вместо чёрного даёт около 0.1, на границе значимости.

### Жёсткие ограничения

- **Лицензии весов: только разрешительные** (Apache-2.0, MIT и подобные). Веса с оговоркой о торговых ограничениях и санкциях (DINOv3 License, SAM License, NVIDIA Open Model License) использовать нельзя. CC-BY-NC и research-only нельзя. AGPL нельзя.
- **Инференс на CPU, не больше нескольких секунд на фото.** Сейчас 879 мс на четырёх потоках.
- **Быстрое дообучение только на замороженном энкодере**, чтобы воркер сервиса успевал переобучаться за минуты на CPU. Полное дообучение возможно отдельной командой на GPU.
- Обучение доступно на Kaggle, 2×T4 по 16 ГБ, сессия до 12 часов.
- Команда из двух человек, осталось около пяти дней, вторая половина занята сервисом, API и инфраструктурой.

### Что ещё не пробовали

Дообучение энкодера (в том числе LoRA), аугментации, нелинейные головы, TTA, мультикроп, оценку глубины, сегментацию пола, детекцию груза, ординальные и распределённые функции потерь, моделирование шума разметки, взвешивание примеров.

## Вопросы к исследованию

Расставлены по ожидаемой пользе. По каждому нужен ответ вида «что именно сделать, чего ожидать по величине выигрыша, чем это подтверждено в литературе или в соревнованиях, какие подводные камни».

1. **Оценка доли занятой площади пола геометрически, а не регрессией по эмбеддингу.** Идея: монокулярная оценка глубины или сегментация плоскости пола → гомография в вид сверху → доля занятой площади считается напрямую. Что из этого реально работает на одной фотографии интерьера без калибровки камеры? Какие модели под разрешительной лицензией годятся (Depth Anything 3 Small/Base под Apache-2.0, что-то ещё)? Есть ли работы по оценке заполненности контейнера, кузова, паллетного места по одному кадру - в логистике, складской робототехнике, оценке объёма мусора в баках? Насколько такой признак дополняет обученную голову, а не заменяет её.

2. **Функция потерь для ограниченной шумной цели со всплеском на границе.** Наша цель лежит в [0, 100], 20% значений ровно 100, разметка глазомерная. Что даёт лучший MAE: регрессия на модуль ошибки, ординальная регрессия по бинам, распределённая или квантильная регрессия с последующим взятием медианы, бета-регрессия, zero-one-inflated модели, «soft labels» по бинам с ожиданием? Что известно про то, как такие постановки взаимодействуют с последующей калибровкой - не съедает ли калибровка весь выигрыш от более умной функции потерь?

3. **Оценка неустранимого пола ошибки при шумной разметке.** У нас есть группы: один и тот же кузов, снятый несколько раз, с отдельными метками у каждого кадра. Можно ли из расхождения меток внутри группы оценить дисперсию разметчика и понять, насколько близко 6.5 к потолку? Какие есть корректные способы это сделать, когда внутри группы физическая загрузка могла и правда отличаться?

4. **Дообучение ViT на 716 фотографиях.** При таком размере линейная голова поверх замороженного энкодера часто не уступает полному дообучению. Что говорят современные сравнения про LoRA, частичную разморозку последних блоков, BitFit, обучение только LayerNorm - на выборках в сотни примеров, для регрессии, а не классификации? Какие гиперпараметры и регуляризация обязательны, чтобы не потерять на такой выборке? Ожидаемая величина выигрыша.

5. **Лучшее сведение патч-токенов в вектор, чем среднее по сетке 4×3.** Мы берём среднее токенов внутри клеток. Что известно про GeM-пулинг, attention-пулинг поверх замороженных токенов, обучаемый лёгкий агрегатор, многомасштабные сетки (1×1 + 2×2 + 4×3 вместе)? Важно: агрегатор должен оставаться дешёвым, потому что кэш эмбеддингов - основа быстрого дообучения.

6. **TTA и мультимасштаб для замороженного энкодера.** Отражение по горизонтали, несколько масштабов, несколько кропов. Что реально даёт выигрыш в регрессии на изображениях и какой ценой по скорости? Есть ли смысл усреднять эмбеддинги, а не предсказания.

7. **Аугментации для задачи, где цель - геометрическая доля.** Какие преобразования сохраняют долю занятой площади пола, а какие её меняют (кроп меняет, отражение нет, перспективные искажения - вопрос)? Что известно про аугментации при обучении только головы поверх замороженного энкодера - имеет ли смысл вообще, если энкодер заморожен.

8. **Калибровка для ограниченной двугорбой цели.** Мы используем медиану в бинах с раздельными кривыми на две популяции. Что ещё применяют: изотоническая регрессия с ограничениями, сплайны, калибровка по квантилям, калибровка с учётом признаков (не только предсказания)? Как не переобучить кривую на 716 точках.

9. **Оценка массы груза по фотографии** - бонусные баллы организаторов, разметки массы у нас нет. Какие есть подходы: классификация типа груза плюс табличные плотности, оценка объёма через глубину плюс плотность, работы по оценке веса в логистике и на складах. Что можно честно отдать пользователю без обучающей выборки - диапазон, интервал, отказ.

10. **Ускорение ViT-B на CPU.** ONNX Runtime, динамическая квантизация в int8, OpenVINO. Насколько падает качество регрессии при int8 для ViT, какие слои обычно оставляют в fp32. Наш запас по времени большой, но скорость входит в экспертную оценку.

## Что было бы полезно на выходе

- Список из 5-10 конкретных проверяемых гипотез, упорядоченных по «ожидаемый выигрыш, делённый на стоимость проверки».
- По каждой: что именно реализовать, на каких данных проверять, какой величины эффект ожидать, чем подтверждено.
- Отдельно - что из перечисленного, скорее всего, **не** сработает на 716 фотографиях и почему: отрицательный результат экономит нам день.
- Ссылки на статьи, соревнования Kaggle с похожей постановкой (регрессия доли или заполненности по одному кадру), открытые реализации под разрешительной лицензией.
