# Что видит модель: карты внимания и вклада

Две карты поверх фото, которые объясняют ответ модели. Прототип на 10 кузовах с замером времени: https://claude.ai/artifact/GUfcJu6J2qQt7MndvZcCkE

| Карта | Что показывает | Цвет | Цена на CPU (M4, 4 потока) |
|---|---|---|---|
| внимание | куда смотрит модель в последнем слое | жёлтый | ~265 мс, один прямой проход |
| вклад в ответ | какой участок тянет процент вверх, какой вниз | красный вверх, синий вниз | ~700 мс, прямой и обратный проход |

Вклад включает в себя и внимание: при `contribution=True` обе карты считаются за один вызов. Отрисовка обеих в PNG - около 60 мс.

## Код

Под порт `LoadExplainer` сервиса достаточно одного вызова:

```python
Explainer.from_package(package, device)          # рядом с предиктором, один раз
explainer.picture(image: PreparedImage, kind) -> bytes   # kind: "attention" | "contribution"
```

`picture` считает только то, что нужно запрошенной карте, и возвращает PNG в размере исходного фото.

Если понадобятся сами числа, есть и раздельные шаги:

- `explainer.explain(image, contribution=True) -> Explanation`: сетки патчей (37×28 для DINOv2 B), `attention` от 0 до 1, `contribution` от -1 до 1 или `None`;
- `heatmap.render(image, explanation, kind) -> bytes`: рисует одну из сеток поверх фото. Сетка кладётся ровно на те пиксели, которые видела модель, с учётом полей при вписывании в окно (`imaging/preprocessing.letterbox_region`).

Предиктор и `application/ports.py` не менялись: объяснение - отдельный класс, ответ модели по-прежнему даёт `PackagePredictor`.

## Как встроить в сервис

1. Загрузить `Explainer.from_package` рядом с предиктором, тем же пакетом. Он держит свою копию энкодера (ещё ~350 МБ памяти для ViT-B): на время вызова он вешает хуки на модуль и не должен мешать предиктору, который в это время отвечает другим запросам.
2. Вызывать под своей блокировкой, по одному: хуки и градиенты не рассчитаны на параллельные вызовы.
3. Импортировать модуль лениво, внутри функции: он тянет torch, а сервисный образ с чисто numpy-пакетом должен работать без него.
4. Одиночное фото: `explain(image, contribution=флаг из интерфейса)`, по умолчанию `True`. Пакетная загрузка: карты не считать вовсе или только `contribution=False`.
5. Порт для слоя `application` - общий контракт, решаем вдвоём. Предложение: `LoadExplainer.explain(image, *, contribution: bool) -> Explanation` отдельным протоколом, ответ API в XML не менять, карты отдавать отдельным запросом как `image/png`.

Веса энкодера грузятся тем же путём, что в предикторе: `load_backbone(member.backbone, device, weights)`.

## Как читать карты

- Вклад на полностью загруженном кузове (около 100%) теряет смысл: модель упирается в потолок, и груз местами синий. Для таких фото показывать внимание.
- Карта объясняет эту модель на этом фото, а не «правду». Если модель ошиблась, карта покажет, на что она опиралась, ошибаясь, и это и есть её польза для оператора.
