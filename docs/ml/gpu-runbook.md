# Сессия на L4: от запуска машины до `/vm_stop`

Все управление идет одним скриптом с рабочего компьютера, `scripts/gpu/remote.sh <шаг>`. Вывод каждого шага пишется еще и в `runs/gpu/<время>_<шаг>.txt`.

## Перед сессией

- Проверить, что команда запускается: `uv run python -m loadvision.cli.commands.finetune --help`. Она не зависит от остальных команд CLI, поэтому поломка в чужой команде сессию не блокирует.
- Отредактировать `scripts/gpu/plan.sh`, то есть список того, что посчитать в эту сессию, по порядку ценности.

## Шаги

1. `bash scripts/gpu/remote.sh upload` отправляет код, данные объемом 354 МБ и эталон для сравнения, то есть предсказания текущей поставки на тех же фотографиях.
2. `bash scripts/gpu/remote.sh setup` выполняется **только в первую сессию** и ставит uv, Python 3.12, зависимости и torch под CUDA 12. Зафиксированный в lock torch собран под CUDA 13. В конце скрипт доказывает, что GPU реально обучает. Окружение остается на диске между остановками.
3. `bash scripts/gpu/remote.sh quick` необязателен и считает один фолд, одна эпоха самой тяжелой модели (728, кроп, глубина), чтобы убедиться, что весь путь работает и влезает в память. Заодно ставит transformers.
4. `bash scripts/gpu/remote.sh start` запускает `plan.sh` на машине в `tmux` и сразу возвращает терминал.
5. `bash scripts/gpu/remote.sh status` показывает, сколько сделано, последние строки логов, загрузка GPU.
6. `bash scripts/gpu/remote.sh fetch-weights` забирает все, а именно прогоны, веса каждого фолда и логи. Шаг сам проверяет, что у каждого прогона веса на месте, и падает, если нет. `fetch` без весов остается для быстрого взгляда на метрики посреди сессии, но перед остановкой машины нужен именно `fetch-weights`.

## Что лежит в папке прогона

Прогон на пяти фолдах:

- `oof.csv`, предсказание каждого обучающего фото моделью, которая его не видела, в формате пайплайна
- `metrics.json`, `mae_raw` до калибровки, `mae` после, флаг `calibrated`, разбивка по фолдам и диапазонам
- `settings.json`, настройки, файл фолдов, коммит
- `folds/fold_<n>/encoder.safetensors` и `head.npz`, веса каждой из пяти моделей фолдов (ViT-B около 350 МБ на фолд); `--no-weights` их не сохраняет
- `test_folds.csv`, предсказание теста каждой моделью фолда, `test_raw.csv` их среднее, то есть готовый ответ прогона для отправки и для ансамбля, без отдельного обучения на всех фото

Прогон на всех фото (`--full`) вместо этого:

- `encoder.safetensors` и `head.npz`, модель в тех двух файлах, которые несет пакет модели для члена ансамбля
- `test_raw.csv`, сырые предсказания теста с полной точностью, из них собирается ансамбль
- `submission.csv`, ответ для платформы

После каждого фолда `oof.csv` сохраняется сразу, так что остановка машины посреди прогона не теряет готовые фолды.
