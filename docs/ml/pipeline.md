# ML-цепочка: от фото до числа

Путей обучения два, и у них общее начало: данные, фолды, препроцессинг.

| Путь | Команда | Зачем |
|---|---|---|
| дообучение | `loadvision finetune` | поставляемая модель v4 |
| замороженный | `loadvision train` | быстрые эксперименты и дообучение голов в воркере |

## Общее начало

### Данные, `ml/data/manifest.py`

Читает `train.csv`, `train_groups.csv` и `images/` в список `Sample`:

```
image_id   img_003649737a27c4e2767c
path       data/train/images/img_003649737a27c4e2767c.jpg
sha256     8ea175ba...     хэш байтов, по нему фото знает сервис
label      10.0            None для test
group_id   grp_e5a7...     None для test
```

Падает сразу, если файла из csv нет на диске или наоборот, есть дубль id, метка не число или вне
0-100, фото без группы или группа без фото. Список сортируется по `image_id`, иначе на разных
машинах вышли бы разные фолды.

### Фолды, `ml/data/splits.py`

Пять фолдов, `StratifiedGroupKFold`. Правила:

- вся группа, то есть один кузов, в одном фолде, иначе модель узнает фон;
- доли меток по корзинам в 10 пунктов разложены ровно, насколько позволяет группировка.

```
fold  photos  scenes  label=100   MAE константы
   0     144     124      18.8%        33.57
   1     143     135      19.6%        33.52
   2     143     132      18.9%        33.52
   3     143     135      19.6%        33.43
   4     143     134      19.6%        33.80
```

Одинаковая MAE константы значит, что фолды равной трудности. Файл `configs/splits/folds.json`
лежит в git, `loadvision data folds` не перезапишет его, если хоть одно фото сменит фолд.
Контракт в [../folds.md](../folds.md).

### Препроцессинг, `imaging/preprocessing.py`

Один код для обучения и сервиса. `resize_pad` вписывает фото в рамку с сохранением пропорций,
делит на 255, нормирует `mean` и `std`. Пропорции не трогаем: растянутый кузов меняет ту
геометрию, которую мы меряем. Интерполяция `bicubic`, на ней учились энкодеры. `baseline_v0`
остается на `bilinear`, потому что повторяет стартовое решение байт в байт.

Рамка, `mean` и `std` берутся из чекпоинта и пишутся в манифест пакета, поэтому сервис готовит
фото теми же числами.

### Виды, `imaging/views.py`

`identity` и `mirror`. Энкодер прогоняет каждый вид и усредняет векторы. У сетки отражение
переставляет колонки, `Backbone.unmirror` возвращает их на место. Список видов входит в
отпечаток кэша.

### Энкодеры, `ml/registry.py` и `ml/models/backbones.py`

Запись реестра: чекпоинт timm, рамка, свертка, препроцессинг, виды, лицензия. Рамка и свертка
входят в ключ, у каждого варианта свой кэш. Записей 16, таблица с замерами в
[methods.md](methods.md). Размерность берется из модели, число 768 нигде не зашито.

## Дообучение: так сделана v4

```
uv run loadvision finetune configs/finetune/dinov2_b14_depth.json --device cuda
uv run loadvision model build-finetuned runs/finetune/<прогон> --version v4
uv run loadvision model register runs/finetune/<прогон>/package
uv run loadvision model activate v4
```

`finetune` на каждом фолде учит свежую копию энкодера вместе с головой и предсказывает фолд,
который модель не видела. Калибровка подгоняется так же, по фолдам. Каждый готовый фолд
сохраняется сразу, остановленная машина его не теряет.

Рецепт v4: DINOv2 ViT-B/14, 15 эпох, L1, шаг 5e-5, батч 16, затухание шага по слоям 0.75,
эпоха прогрева, дальше косинус, bf16. Глубина от Depth Anything V2 Small идет в голову сеткой
16x12. Пять моделей фолдов на L4 за 12 минут.

`build-finetuned` собирает пакет из пяти моделей фолдов, усредненных в равных долях, с
калибровкой и метриками того же прогона. `--full` учит одну модель на всех фото, `blend`
усредняет несколько прогонов и меряет смесь по фолдам.

Что лежит в папке прогона и как гонять это на арендованной GPU, в
[gpu-runbook.md](gpu-runbook.md).

## Замороженный путь

```
uv run loadvision train configs/experiments/<имя>.json --device mps
```

Энкодер заморожен, учится только ридж-голова поверх его вектора. Вектор фото не зависит от
головы, калибровки и фолдов, поэтому считается один раз, и любой опыт с головой стоит секунды.
Этим путем найдены свертка, калибровка и состав ансамбля из [methods.md](methods.md). Воркер
идет этим же путем, когда дообучает головы v4 на подтвержденных метках, см.
[model.md](model.md).

Этапы лежат в `ml/pipeline/stages/`, каждый реализует протокол `Stage` с методом `check` для
постусловий:

| Этап | Что делает |
|---|---|
| `BuildManifest` | список фото |
| `ExtractEmbeddings` | векторы в кэш |
| `TrainFolds` | головы и калибровка по фолдам |
| `Evaluate` | метрики по OOF |
| `PredictTest` | `submission.csv` |
| `BuildPackage` | пакет для сервиса |

Если этап нарушил постусловие, прогон останавливается на нем и пишет причину в `summary.json`.

**Кэш эмбеддингов.** `runs/cache/embeddings/<ключ>.npz`, ключ это sha256 фото, а не имя файла.
Файл подписан отпечатком препроцессинга: хэшем обработки фиксированной синтетической картинки.
Сменился `mean`, рамка или код `resize_pad`, и кэш отвергается с понятной ошибкой. На маке
около 2 минут на энкодер на 1023 фото, повторный прогон секунды.

Каждая голова обрезает ответ в 0-100 до усреднения ансамбля, и при обучении, и в сервисе.
Ридж отвечает и 111, и -19, и когда обучение обрезало каждого члена, а сервис только среднее,
131 фото из 716 расходились до 3.65 пункта. Теперь
`tests/ml/test_stages.py::test_the_package_answers_exactly_what_the_submission_says` сверяет
ответы пакета с `submission.csv` построчно.

**Метрики**, `ml/evaluation/metrics.py`: `mae`, `within_10`, `bias`, `p95_error`, MAE на 0-20,
20-80, 80-100, по каждому фолду и разброс между ними.

## Постобработка

Применение в `ml/postprocess.py` на чистом numpy, подгонка в `ml/training/postprocess_fit.py` на
scikit-learn. Пороги и коэффициенты попадают в манифест как `params`, кривые калибровки
отдельным `.npz` из двух массивов, без pickle. Пропорции кадра для `_by_aspect` сервис берет из
`PreparedImage`, новых входов не нужно. Все шаги и замеры в [methods.md](methods.md).

## Пакет модели, `ml/packaging/`

```
package/
  manifest.json                 члены, препроцессинг, цепочка, CV-метрики, хэши файлов
  m<n>/                         головы членов ансамбля
  weights/*.safetensors         веса энкодеров
  depth/                        сеть глубины, если пакет ее называет
  postprocess/step_<n>.npz      кривые калибровки
  ood/reference.npz             эмбеддинги train для непохожести сцены
  licenses/                     тексты лицензий и NOTICE
```

Лицензия записана в каждой строке реестра без значения по умолчанию, и если для нее нет текста
в `licenses/`, сборка падает. Члены с одним чекпоинтом ссылаются на один файл весов.

Сборка в конце грузит пакет настоящим `PackagePredictor` и предсказывает им, так что
непригодный для сервиса пакет не выйдет. torch импортируется лениво: пакет без torch-членов
грузится в образе без torch.
